# 需求文档：设备心跳监控系统

## 1. 背景与目标
当前项目需要一个机制来监控各设备的在线状态。目标是实现一个轻量级的心跳监控系统，允许各设备上报心跳，并提供一个Web页面展示当前在线设备列表。

## 2. 功能需求

### 2.1 心跳上报接口
- **功能**: 接收设备发送的心跳信息。
- **输入参数**:
    - `device_name` (设备名称，字符串)
    - `timestamp` (时间戳，整数或浮点数，表示设备当前时间)
    - (可选) `ip_address` (设备IP地址，如果可能的话从请求中自动获取)
- **处理逻辑**:
    - 记录或更新设备的最后心跳时间。
    - 如果设备不存在，则创建新记录。
- **响应**: JSON格式，包含状态码和消息。

### 2.2 在线设备查询接口
- **功能**: 获取当前在线的设备列表。
- **输入参数**: 无（或可选过滤条件）。
- **处理逻辑**:
    - 查询所有设备记录。
    - 判断设备是否在线（例如：最后心跳时间在最近5分钟内）。
    - 返回设备列表，包括设备名、最后心跳时间、在线状态等。
- **响应**: JSON格式，包含设备列表。

### 2.3 监控页面
- **功能**: Web页面展示设备在线状态。
- **设计参考**: 参照 `timestamp.html` 的样式和交互。
- **内容**:
    - 标题：设备在线监控。
    - 列表/表格：显示设备名、最后心跳时间、状态（在线/离线）。
    - 自动刷新：页面应定时自动刷新数据（如每10秒）。

### 2.4 主页入口
- **功能**: 在主页 (`homepage.html`) 添加一个链接或按钮，点击后跳转到监控页面。

## 3. 非功能需求
- **数据库**: 使用项目现有的 SQLite3。
- **兼容性**: 接口应易于被其他语言（如 Python, C++, etc.）调用。
- **性能**: 能够处理适量的并发心跳请求。

## 4. 接口规范
参照 `timestamp.html` 中的 `fetch` 调用方式：
- 方法: `POST` (用于上报), `GET` (用于查询)
- 响应格式:
  ```json
  {
      "code": 200,
      "data": { ... },
      "message": "success"
  }
  ```
